# 아크포인트 스튜디오 — 트리거 GTM 루프

Clone Loop Day 에이전틱 GTM 해커톤 제출물 (2026-10-24)
운영 2026-10-25(일) ~ 10-31(토) · 결과 공유 11-01 Discord

아크포인트 스튜디오는 의원의 네이버 블로그 원고와 카드뉴스를 매주 만들어, 원장이 손대지 않아도 발행까지 이어지게 하는 콘텐츠 서비스입니다. 이 레포는 그 서비스를 **실제 병원**에 알리기 위한 7일짜리 에이전트 루프의 설계와 검문 도구입니다.

## 한 줄 정의

병원이 블로그 문제를 **지금** 겪고 있다는 공개 신호 두 가지(신규 개원, 발행 단절)를 에이전트가 매일 감지해 "트리거 지도"를 만듭니다. 이 지도로 광고 지역, 어필리에이트 매칭, 파운더 글 주제를 고릅니다. 그리고 들어온 신청 병원이 모집단보다 트리거 병원에 몰리는지로 "타이밍이 효과가 있는가"를 판정합니다.

## 무엇이 새로운가

운영 허브 문서 153개 중 150개 본문(첨부 제외)과 대조했습니다. `개원`, `트리거`라는 표현은 한 번도 나오지 않아, 열람한 범위 안에서는 검토 기록이 없는 축입니다. 단, 어필리에이트 보상은 기존 "이음 외 기관 파트너 보상" 구상의 변형이고, T3가 쓰는 발행 기록은 이미 검토된 블로그 진단안(EUM-50)과 데이터 원천이 같습니다. 진단 리포트처럼 고객에게 보내지 않고 트리거 감지에만 씁니다.

| 새 방식 | 기존 방식과 다른 가정 |
|---|---|
| **T1 신규 개원**: 심평원 개설일 90일 이내 의원 | "관심 적은 병원 일반"이 아니라 블로그를 0에서 시작하면서 업체를 지금 고르는 병원 |
| **T3 발행 단절**: 6개월간 주 1회 이상 쓰다가 최근 28일 0건 | 대행사 해지나 담당자 퇴사로 생긴 전환 순간 |
| **트리거 지도 → 집행 위치** | 광고 지역·크리에이터·글 주제를 감이 아니라 오늘 트리거가 많은 구와 트리거 종류로 고름 |
| **트리거 농축도 측정** | 클릭·신청 수가 아니라 "신청 중 트리거 병원 비율 ÷ 모집단 비율"로 타이밍 효과를 봄 |

이미 검토했거나 시행 중인 것(이음 CSO 소개, 무료 샘플로 유입, 블로그 진단 리포트, 가격 안내 페이지, 카카오 채널)은 진입 장치로 쓰지 않습니다. 우편 DM, 채용공고 감지, 1:1 콜드 메일·문자도 넣지 않았습니다. 대조표는 [GTM-LOOP.md §1](GTM-LOOP.md#1-새로움-검사--기존-제안시행-중인-것과의-대조)에 있습니다.

## 타겟 고객과 봇 차단

**ICP**: 심평원에 등록된 서울 **의원급** 요양기관(내과·피부과·비뇨의학과부터 시작), 마케팅 저관여, 상위 노출 패키지를 크게 집행하지 않는 곳.

**실제 고객 판별 하드 게이트** — 다섯 개를 모두 통과해야 집계합니다.

| ID | 게이트 | 판정 근거 |
|---|---|---|
| G1 | 요양기관 실재 | 심평원 조회 ykiho, 응답 sha256 해시 저장 |
| G2 | 운영 중 | 폐업 정보 없음 + 플레이스 영업 정보 |
| G3 | 블로그 실재 | `blog.naver.com/{id}` 응답 + 병원명·주소 일치, 또는 블로그 없음(`no_blog`, 신규 개원 병원은 대부분 여기에 해당) |
| G4 | 사람 접점 | 일회용 아닌 이메일, 플레이스 주소가 G1과 일치, 개인정보 동의 |
| G5 | 봇 신호 없음 | `disposable_email`, `place_mismatch`, `same_email_multi`, `burst_submit` 중 2개 이상이면 탈락 |

신청 병원은 모집단과 **같은 규칙, 같은 증거 형식**으로 트리거를 분류합니다. 트리거 날짜는 개설일이나 마지막 게시일에서 나오므로, 언제 조회했는지에 따라 결과가 바뀌지 않습니다. 적합도 점수(C1~C5, 100점)는 제작 대기열이 상한을 넘을 때의 제작 순서와 유료 안내 순서를 정할 때만 쓰고, 판정에는 쓰지 않습니다.

## 핵심 메트릭

**North Star — TVR (Trigger-Verified Request)**
이음 경유가 아닌 신청 중, 신청 시점에 트리거 유효기간(T1 90일, T3 30일) 안이었고 G1~G5를 모두 통과한 샘플 신청 건수 (ykiho 중복 제거).

**타이밍 가설 H-T 판정**

| 항목 | 규칙 |
|---|---|
| Lift | ((k + 0.5) / (n + 1)) ÷ 모집단 트리거 비율 p₀ |
| p값 | 한쪽 이항검정 P(X ≥ k \| n, p₀) |
| 지지 | 트리거 신청 k ≥ 2, Lift ≥ 2, p < 0.10 |
| 표본 부족 | 모집단 안 검증 신청 n < 5 |
| 그 외 | 미확정 → 7일 더 측정 (7일 안에는 "기각"을 내지 않음) |

**가드레일 (위반 시 해당 채널 즉시 정지)**: 광고·경제적 이해관계 표기 누락 1건, 상위 노출·예약 보장 문구 1건, 공개 채널 가격 노출 1건, 광고 7일 지출 상한 초과, 소스별 봇률 30% 초과(유입 5건 이상인 소스).

## 루프 구조

```
[Trigger Watcher] ──→ population.csv + 트리거 지도(구별 T1·T3 수)
 (T1 심평원 / T3 RSS)        │
                            ↓
                   [Channel Planner] → [Copywriter] → [Channel Runners]
                (광고 지역·키워드 그룹,              (검색광고·어필리에이트·파운더 글)
                 크리에이터 후보, 글 주제)                    │
                            ↑                               ↓ 신청
   [Analyst] ← [Sample Queue(기존 절차)] ← [Scorer] ← [Inbound Verifier]
       └── 다음 날 조정: 트리거별 Lift·CPTVR로 지역·예산·문안 갱신
```

8단계 에이전트마다 입력, 출력, 검증 가능한 PASS 조건이 있습니다 ([GTM-LOOP.md §6](GTM-LOOP.md#6-에이전트-루프-구조)). Analyst는 매일 아래 규칙을 자동 적용합니다.

- 광고 상한 절반을 쓸 때까지 광고 TVR이 0이면 광고 정지
- 트리거 그룹별 CPTVR이 평균의 2배를 2일 연속 넘으면 그 그룹 예산의 50%를 CPTVR이 가장 낮은 그룹으로 이동
- 광고 지역은 매일 트리거 지도 상위 구로 갱신
- 샘플 대기열이 20건을 넘으면 광고 예산 50% 감액
- 불쾌감 회신이나 신고가 1건이라도 오면 해당 문안은 사람이 다시 승인할 때까지 정지

## 실행 채널

| 채널 | 트리거 연결 |
|---|---|
| 퍼포먼스 마케팅 자동화 | T1 개원·T3 대행 교체 키워드 그룹. 광고 지역을 트리거 지도 상위 구로 매일 갱신. 일 예산은 `min(Σ 키워드별 월평균 클릭 ÷ 30 × 예상 CPC, 남은 상한 ÷ 남은 일수)`. 7일 상한은 "첫 달 매출 × 목표 유료 1건"으로 잡아 고객 획득 비용이 첫 달 매출을 넘지 않게 함 |
| 마이크로 인플루언서 매칭 | 병원 실장·코디네이터 크리에이터(T3 당사자), 개원 준비 원장 크리에이터(T1 당사자). 공개 게시물로 점수화해 매칭(실장: 실무 게시 비율 × 참여율, 원장: 개원 관련 게시 비율 × 최근 90일 활동). 소개 병원이 유료 신청하면 첫 달 이용료 10% 정산 |
| 파운더 마케팅 | "개원 D-90~D+90 블로그 체크리스트"(T1), "대행사를 바꿀 때 블로그가 멈추지 않게 하는 법"(T3). 좋아요가 아니라 UTM으로 TVR을 셈 |

신청이 들어오면 기존 무료 샘플 절차로 처리합니다. 새 랜딩이나 새 상품은 만들지 않습니다.

## 검문기 실행

모든 수치는 원장 행으로 역추적됩니다. 검문기는 표준 라이브러리만 씁니다 (Python 3.9+).

```bash
# 운영 원장 검사 (종료 코드 0 = 위반 없음, 1 = 위반 있음)
# 광고 7일 상한은 병원가 비공개 원칙(D6)에 따라 레포에 적지 않고 실행할 때 넣습니다
export GTM_AD_CAP_7D_KRW=<상한 금액>
python3 validate_ledger.py ledger.csv --stats channel_stats.csv --pop population.csv --guard guardrail_log.csv

# 가상 샘플 데이터로 시연 (상한 300,000원은 시연용 가상 값)
python3 validate_ledger.py ledger.sample.csv --stats channel_stats.sample.csv \
  --pop population.sample.csv --guard guardrail_log.csv --now 2026-10-31T23:00:00 --ad-cap 300000
```

상한을 넣지 않은 채 광고 지출이 기록되면 검문기가 위반으로 처리합니다.

샘플 데이터(가상 병원 6곳) 실행 결과 일부입니다.

```
L3 신청: 5 / L4 검증 신청(VSR): 4
L5 TVR(NSM): 2 (T1 1, T3 1)
제외(이음 CSO 경유): 1행
전체: 모집단 안 검증 신청 4건 중 트리거 2건 | 모집단 비율 7.6% | Lift 6.54 | p=0.032 → 표본 부족 | 지지 문턱: 신청 5건 중 2건
== 위반 ==
총 0건
```

봇 샘플 1건은 G4·G5 탈락으로 VSR에서 빠지고, 이음 경유 1건은 집계에서 제외되며, 유효기간이 지난 개원 병원 1건은 TVR에 들어가지 않습니다.

## 현재 상태와 남은 일

- **운영 전입니다.** 실제 신청·매출 수치는 아직 0이며, 위 수치는 가상 샘플입니다. 실측 결과는 11-01에 공유합니다.
- **착수 전 확인할 것**: 광고 7일 상한 금액 확정(레포 밖에서 관리), 그리고 외부 사실 3건(심평원 API의 개설일자 필드 응답, 네이버 키워드 도구 클릭수·CPC, 검색광고 지역 타겟팅 단위).
- **사람이 하는 일**: 광고·글 문안 승인, 샘플 제작(기존 절차), 병원 응대, 어필리에이트 정산.
- 7일 결과는 방향 판단용입니다. 신청은 트리거에 맞춘 채널로 모이므로, 이 판정은 "트리거 맞춤 채널이 트리거 병원을 데려오는가"를 보는 것이고 타이밍의 순수한 인과 효과는 아닙니다.
